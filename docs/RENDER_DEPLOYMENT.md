# Deploy Closet Craft on Render

## One-click setup

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/gargidev/ClosetCraft)

The button opens Render's Blueprint flow using the `render.yaml` in this repository. Sign in to Render, review the services and estimated costs, and approve creation. This is a deployment setup link, **not a live application URL**.

## Services created

- **Frontend:** React 18 + Vite static site.
- **API:** Existing Node.js + Express + Prisma backend.
- **ML service:** Existing FastAPI + PyTorch/CLIP service.
- **Database:** Managed PostgreSQL.
- **Uploads:** Persistent Render disk attached to the API service.

This Blueprint deliberately deploys the architecture that currently exists in the repository. The repository is not currently a FastAPI + SQLite-only backend; it has an Express/Prisma/PostgreSQL API and a separate FastAPI ML service. Switching the main API and database to SQLite would be a separate migration and is not silently performed by this deployment configuration.

## Deployment steps

1. Open the Deploy to Render button above.
2. Connect GitHub and select `gargidev/ClosetCraft`.
3. Review the Blueprint resources and costs. The ML service uses PyTorch/Transformers and needs enough memory and disk to download/load the CLIP checkpoint.
4. Approve deployment.
5. Wait for all services to finish building and become healthy.
6. Open the generated static-site URL and test registration, login, wardrobe operations, image upload/classification, outfit generation, and saved outfits.

Render may require a paid plan for the persistent disk, database, and ML service. Check the current plan/pricing before approving.

## Environment and safety

- `JWT_SECRET` is generated by Render.
- `DATABASE_URL` is injected from the managed PostgreSQL database.
- `ML_SERVICE_URL` uses Render's private service network.
- `FRONTEND_URL` and `VITE_API_URL` are populated from the generated service hosts.
- Do not commit production secrets.
- The API upload directory is mounted to a persistent disk so uploaded images survive service restarts.

## Health checks

- API: `https://<api-host>/api/health`
- ML: `https://<ml-host>/health` (private service may not have a public URL)
- Frontend: `https://<site-host>`

## Important pre-production checks

The current repository still needs an end-to-end production smoke test after deployment. In particular, verify Prisma schema synchronization, user-scoped persistence, file upload persistence, ML model startup/memory requirements, CORS, and the frontend-to-API connection. Do not publish the site URL as production-ready until those checks pass.
