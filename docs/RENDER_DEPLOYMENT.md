# Deploy Closet Craft on Render

## One-click setup

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/gargidev/ClosetCraft)

The button opens Render's Blueprint flow using the `render.yaml` in this repository. Sign in to Render, review the services and estimated costs, and approve creation. This is a deployment setup link, **not a live application URL**.

## Services created

- **Frontend:** React 18 + Vite static site.
- **API:** Existing Node.js + Express + Prisma backend.
- **ML service:** Public FastAPI + PyTorch/CLIP web service, with `/health` health check.
- **Database:** Managed PostgreSQL.
- **Uploads:** Persistent Render disk attached to the API service.

The ML service is intentionally configured as a public web service so it receives a public HTTPS hostname. The API service receives that hostname through the `ML_SERVICE_URL` environment variable. The FastAPI app binds to `0.0.0.0:8000` in its Dockerfile and exposes `/health`.

**Security note:** The ML endpoints are currently not protected by API-key or user authentication. Making this service public means anyone who discovers its URL can call its inference endpoints. Before production use, add rate limiting and service-to-service authentication or restrict the endpoints behind the API. Do not expose secrets in frontend variables.

This Blueprint deploys the architecture currently present in the repository: Express/Prisma/PostgreSQL for the main API and a separate FastAPI ML service. It does not silently migrate the backend to SQLite.

## Deployment steps

1. Open the Deploy to Render button above.
2. Connect GitHub and select `gargidev/ClosetCraft`.
3. Select branch `main` and Blueprint path `render.yaml`.
4. Review all resources and current plan costs. The ML service uses PyTorch/Transformers and needs sufficient memory and disk to download/load its model checkpoint.
5. Approve deployment.
6. Wait for the frontend, API, database, and public ML service to finish provisioning and become healthy.
7. Open the generated ML service URL and check `/health`. Then test the frontend's registration, login, wardrobe operations, image upload/classification, outfit generation, and saved outfits.

Render may require paid plans for the database, persistent disk, and ML service. Check the current pricing before approving.

## Environment and safety

- `JWT_SECRET` is generated by Render.
- `DATABASE_URL` is injected from the managed PostgreSQL database.
- `ML_SERVICE_URL` is populated from the public ML web service hostname.
- `FRONTEND_URL` and `VITE_API_URL` are populated from generated service hosts.
- Do not commit production secrets.
- The API upload directory is mounted to a persistent disk so uploaded images survive service restarts.

## Health checks

- API: `https://<api-host>/api/health`
- ML: `https://<ml-host>/health`
- Frontend: `https://<site-host>`

## Important pre-production checks

The repository needs an end-to-end production smoke test after deployment. Verify Prisma schema synchronization, user-scoped persistence, file upload persistence, ML model startup/memory requirements, CORS, the API-to-ML connection, and the frontend-to-API connection. Do not publish the site URL as production-ready until those checks pass.
